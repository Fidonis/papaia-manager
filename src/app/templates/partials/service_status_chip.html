{# Aggregate status, rendered into the header of every page. One chip, not two pills. The two pills this replaces sat in the same `shrink-0` box as the page's primary action and competed with it for the right-hand corner; worse, their text length varied with the state, so the header reflowed on every poll. The chip is a fixed width and always says the same amount, and the breakdown moved into the popover behind it. It is also deliberately not a `badge`: as an outline badge it carried the same visual weight as the decorative `v1.2` / `enabled` badges everywhere else in this panel and read as decoration rather than as a state. Core and add-ons still do not share a verdict. The chip aggregates them for its one line -- `worst()` in the router decides that, so the severity order lives in one place -- but the popover keeps the two apart, so a broken add-on out of a customer catalogue cannot make the core stack look down. Nothing here names a service, for either role: a non-admin learns that something is wrong without learning what, which is the point of putting it in front of them at all. Only the link is admin-only -- /services enforces the admin role itself, so pointing everyone at it would hand non-admins a chip that answers with 403.
